# 查询结果交付与文件导出设计

设计确认日期：2026-09-14  
状态：本轮 API/DAS 实现与验收完成；Web 与 Harness 实际接入按后续阶段实施  
关联文档：[产品需求](./requirements.md) · [技术方案](./technical-design.md) · [共享合同](./contracts.md) · [API 实施方案](./api-implementation-plan.md) · [DAS 实施方案](./das-implementation-plan.md)

## 1. 交付目标

一次查询由 API 确定业务语义、当前用户授权范围和输出脱敏规则，DAS 在资源预算内执行并返回标准化结果。当前前端会话取得完整结果后，在浏览器中完成表格分页、虚拟滚动与 Excel、Word、PDF 文件生成。

完整结果指本次已确认条件与授权范围内、预算允许交付的全部结果行。它可以是明细表，也可以是查询产生的分组结果表。每份结果都必须说明完整性；达到资源边界时，明确返回截断状态或失败原因，使使用者能够判断结果可用于哪些结论和导出。

本设计覆盖查询结果从 DAS 到 API、模型分析、Web 展示和文件生成的职责分工。分析运行的事务状态、工具幂等、取消、租约、证据与历史报告快照继续使用既有机制。

## 2. 职责与数据流

| 层次 | 责任 | 向下游交付的内容 |
| --- | --- | --- |
| API 授权与查询 | 校验对象、列、行范围、指标口径、关系、参数和运行归属，签发最终 DSL | 已签名的 `{ access, query, signature }` 与短时 JWT |
| DAS | 校验请求与本地对象白名单，执行只读查询，标准化、脱敏并控制资源 | 有界结果、列定义、实际行数、完整性和数据新鲜度 |
| API 结果交付 | 校验 DAS 结果与当前访问权，为浏览器交付完整结果，为分析提供受限证据 | HTTP 结果、结果摘要、查询关联和必要分析表 |
| 分析运行与 SSE | 保存运行状态、步骤、证据摘要和事件；通知分析进展、结论及结果状态 | 面向用户的文字、图表、必要汇总表与结果关联 |
| Web | 在当前会话中持有结果，计算分页、虚拟渲染并生成文件 | 可交互表格及浏览器下载文件 |

浏览器始终通过 API 访问结果。完整明细复用现有 `POST /query` 的 HTTP 响应到达浏览器。模型上下文和 SSE 使用分析所需的受限内容；完整明细的数量增长由结果交付链路承载。

模型取得的摘要必须保留实际行数、完整性、条件、数据时间和证据关联。需要进一步分析时，通过受控查询或确定性计算取得适当的聚合证据。模型收到的有限预览只支持其包含范围内的判断。

## 3. 完整性与资源预算

### 3.1 结果语义

- `columns` 与 `rows` 继续使用共享结果合同，列名唯一，行字段和单元格类型与列定义一致。
- `row_count` 表示当前交付的实际行数，并与 `rows.length` 相等。
- `truncated` 表示本次结果是否因查询或连接器的限制被裁剪。只有结果完整时，`row_count` 才同时表示本次结果的精确总行数。
- `delivery` 为兼容历史保存内容的可选字段，新 DAS/API 响应明确填写：完整结果使用 `{ status: "complete", total_row_count: row_count }`；截断结果使用 `{ status: "truncated", total_row_count: null }`，并与 `truncated` 保持一致。
- 截断结果展示“已返回行数”和截断原因；其完整业务结果总行数、总页数在未取得可靠依据时保持未知。
- 空结果保留列定义。完整空结果的总行数与总页数均为 0，浏览器禁用翻页及跳页操作。
- Web 后续从请求上下文、已有查询结果和保存的快照中组合查询条件、数据来源、可用指标版本及数据时间，用于展示和导出。查询响应沿用可选 `freshness`；快照已有生成时间与来源信息按原含义展示，数据更新时间和生成时间分别标注。

完整性是端到端约束：连接器探测、DAS 返回、API 校验、分析证据、Web 提示和导出必须保持一致。关系查询继续使用 N+1 行探测验证超过返回上限的情况；参数化固定输出按实际结果及其连接器能力验证。

### 3.2 预算执行

一次查询同时受行数、结果字节数与时间预算约束。DAS 执行实际资源限制，API 的请求等待与响应接收预算须能够配合该交付范围。配置必须经过 Schema 校验，明确默认值、可配置范围与硬上限。

| 预算 | 约束用途 | 验收要求 |
| --- | --- | --- |
| 返回行数 | DSL `limit` 与数据源 `row_limit` 硬上限均为 100,000；普通查询实际取两者较小值，省略 `limit` 时使用管理员配置 | 少于、恰好等于和超过上限时的完整性准确，返回量受限 |
| 结果字节 | 标准化 `{ columns, rows }` 的 JSON UTF-8 大小最多 32 MiB；API→DAS 查询响应传输另预留 64 KiB 元数据 | 宽行及超限结果返回 `QUERY_LIMIT_EXCEEDED`，中止结果交付 |
| 查询时间 | 数据源 `timeout_ms` 沿用 100–120,000 ms；API→DAS 查询请求等待预算为 135,000 ms | DAS 执行与排队达到截止后停止交付；API 等待覆盖最长执行预算及传输余量 |
| 运行证据 | 查询结果最多 5,000 行，完整 QueryResult 的 JSON UTF-8 大小最多 2 MiB | 超过任一容量边界时拒绝进入证据事务 |
| SSE 表格 | 最多 100 行样本，`{ columns, rows }` 的 JSON UTF-8 大小最多 256 KiB，包含固定键与括号开销 | 样本受行数和字节约束，并保留原始结果行数、截断与采样标记 |

完整结果超过预算时，系统说明已触达的边界，并支持用户调整查询条件后创建新的查询。截断预览应明确其范围；“完整明细导出”仅适用于已取得完整结果的情况。导出不得把截断预览标成完整数据。

本轮保持现有管理员配置，行数硬上限提高后由实际请求和数据源配置共同确定交付量。SQL Server 逐行读取，仅保留有效行数上限加 1 行用于截断探测。固定输出过程的其余行继续消费，同时检查多结果集；超出 32 MiB 字节预算时取消原生请求。MySQL、PostgreSQL 使用驱动缓冲结果，再进行标准化和公共结果预算检查；各驱动的实际内存范围按其读取方式验收。

所有新增时间生成、解析、加减、比较和格式化统一使用 `dayjs`；业务日期时间使用东八区约定。以上预算与合同已完成本轮 API/DAS 实现，验证范围见第 8.5 节。

## 4. 当前会话与运行持久化

浏览器取得完整结果后，由当前会话的数据状态持有行数组和结果元信息。页码、每页条数与渲染窗口只是该结果的展示状态，翻页和跳页直接读取已有行数组。

对纳入分析运行的查询，API 保存运行归属、已确认条件、最终 DSL、查询标识、完整性、摘要、证据和幂等记录，以满足既有恢复与审计要求。运行查询将缺省 `limit` 归一化为 5,000，再进行幂等请求比较；返回证据受 5,000 行及 2 MiB JSON 容量约束，保持原有权限与恢复语义。

普通 `POST /query` 返回完整明细，结果行由当前前端会话持有；API 持久化范围由运行证据和明确保存的报告内容决定，普通查询明细不落库。交付前通过 `refreshContext` 从数据库复查身份与权限，重新授权并比较最终 DSL 和 `output_masks`；授权结果变化时拒绝交付。成功响应使用 `Cache-Control: no-store`。

当前运行的工具幂等规则继续有效：相同操作标识的重试不得重复提交证据、事件或终态。普通 `POST /query` 按每次显式提交执行查询，结果交付前复查当前权限；运行工具按原有操作标识和已提交记录处理重试。SSE 重连与文件导出复用已有内容。

新 SSE `table` 事件包含可选 `result_row_count`、`result_truncated` 和 `sampled`。前两者保留原始结果的实际交付行数及截断状态，`sampled` 表示事件行数少于原始交付行数；采样与数据源截断分别表达。字段保持可选，已有持久化事件继续可读。

刷新后可以重新加载已保存的会话或报告内容，并重新检查当前权限。当前会话中的明细尚未保存时，界面明确其可用状态；需要重新查数时，用户发起新的查询运行。

## 5. Web 表格交互（后续实施）

表格控件基于浏览器中的完整结果提供：

- 当前页码、每页条数、上一页、下一页和指定页跳转。
- 真实总行数和总页数；总页数为总行数除以每页条数后向上取整。
- 修改每页条数后的有效页码校正，避免越界和空白页。
- 大结果的虚拟滚动，仅渲染可见区域及必要缓冲，保持滚动与操作流畅。
- 查询条件、数据时间、完整性与截断提示，便于用户判断结果范围。

分页决定当前展示的行范围，虚拟滚动决定当前创建的渲染节点，两者共同使用同一份结果。用户切换页码、页大小或跳页时，由前端计算切片，数据总量保持一致。

该部分列入 Web 实施与浏览器验收。本轮 API/DAS 完成情况不代表前端分页、虚拟滚动或导出界面已完成。

## 6. 文件内容与生成方式（Web 后续实施）

Excel、Word、PDF 均由浏览器使用当前已取得的数据与分析内容，或 API 授权后加载的历史快照生成。API 可以读取已保存内容、校验报告权限及完整来源范围；文件生成使用已有数据，导出动作不再次执行数据库或业务 HTTP 查询。

| 格式 | 主要内容 | 使用方式 |
| --- | --- | --- |
| Excel | 完整明细表或完整查询结果表，以及查询条件、数据时间、列说明与必要来源信息 | 核对、筛选和继续处理数据 |
| Word | 用户可见的会话内容、用户问题、澄清及回答、分析说明、图表、必要汇总表、结论和证据 | 编辑、整理和归档沟通与分析过程 |
| PDF | 分析说明、图表、必要汇总表、结论和来源信息 | 固定版式阅读、打印和分发 |

### 6.1 Excel

Excel 导出覆盖完整结果中的全部行，不受当前页码、每页条数或虚拟滚动窗口影响。多张结果表按业务含义组织工作表，查询条件与数据时间清晰可见。整数、小数、文本、日期和空值按共享数据合同保留含义；文件格式化应便于阅读并保持数值可核对。

大批量明细以 Excel 承载。浏览器生成前检查完整性与所需数据是否可用；结果被截断时，先提示用户缩小查询范围取得完整结果。

### 6.2 Word

Word 按会话顺序组织用户可见的问题、澄清选项及确认结果、分析说明和结论，关联必要的图表、汇总表及证据。文字与表格可编辑，图表可嵌入图片，便于用户继续整理报告。

内容以沟通记录和分析报告的阅读需求组织。详细数据通过对应的 Excel 文件提供；Word 中保留理解分析所必需的汇总表、条件和数据时间。

### 6.3 PDF

PDF 根据分析文档生成固定版式，保证中文、图表、表格、标题和分页可读。长表按合理页宽排布，保留必要表头和来源说明。内容聚焦分析、图表、汇总与结论，大批量明细由 Excel 提供。

### 6.4 共同验收

- 同一结果的三种格式从请求与已有元信息组合一致的条件、数据时间、可用指标版本及完整性说明。
- Excel 包含全部可导出结果行；Word 的文字与表格可编辑、图表可嵌入图片；PDF 在阅读和打印尺寸下布局清晰。
- 文件生成采用已有数据或授权后的保存内容，验收时确认导出前后业务查询执行次数保持不变。
- 浏览器明确展示生成过程与失败说明，数据不可用、结果不完整或权限校验失败时准确提示。

## 7. 历史报告与权限

历史快照的读取、分享和导出同时检查报告访问权及当前访问者对快照完整来源范围的权限。来源范围覆盖表格、图表、文字结论、汇总与证据所使用的数据源、对象、字段、行范围和脱敏要求。权限不足或无法证明完整覆盖时，API 拒绝交付原快照；用户可以按当前权限新建查询。

浏览器导出历史报告时使用已经通过上述校验的快照内容。API 的授权检查与保存内容读取保持既有范围；同一份历史快照的查询条件和数据时间保持其生成时的含义。

## 8. 实施安排与验收

### 8.1 本轮 API/DAS 工作（已完成）

1. 定义有界结果的 `delivery` 完整性与 SSE 样本关联合同，落实行数、字节和时间预算。
2. 在 API 查询交付、DAS 规划与连接器执行中落实预算，保持现有授权、签名、标准化、脱敏、审计和取消链路。
3. 落实运行证据 5,000 行/2 MiB、SSE 表格 100 行/256 KiB 预算与原始结果关联字段，保持权限与幂等语义。
4. 验证 HTTP 结果交付与当前运行幂等、权限复查和历史快照读取的衔接。

### 8.2 Web 后续工作

1. 实现当前会话完整结果状态和 HTTP 结果读取。
2. 实现页码、页大小、上一页/下一页、跳页、真实总数和虚拟滚动。
3. 基于第 6 节内容分工实现浏览器 Excel、Word、PDF 生成。
4. 完成浏览器分页、文件内容、可编辑性、版式和导出查询次数验收。

### 8.3 Agent 工具后续接入

Harness 的完整工具适配随对话执行链路推进。模型工具应返回受限摘要、必要分析表、完整性和证据引用，并与浏览器的完整结果交付衔接。该能力在 Agent 接入后独立验收。

### 8.4 基线与后续范围

JWT 签名、有效期、请求绑定与 `jti` 必需字段校验继续作为现有授权基线。严格单次消费 `jti` 的设计和高精度十进制合同后续单独推进；当前整数与小数沿用共享数值合同。Oracle 的新增实现与真实环境验收按后续阶段安排，已完成的连接器基础记录保留。
