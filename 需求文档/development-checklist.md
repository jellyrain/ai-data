## 0. 使用方式

- `[ ]` 表示未完成，`[x]` 表示已完成，`[-]` 表示暂不执行。
- 各章节按组件分类，实际交付按第 0.1 节推进；完成相应验收后再扩展下一阶段。
- 先打通一条真实业务链路，再扩展表、指标和角色，不先做大而全的平台。
- 所有查询只能走 DSL；业务数据库只允许 `SELECT`。

### 0.1 交付顺序

| 顺序 | 交付重点                                                          | 验收目标                                                               |
| ---- | ----------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1    | 在已有 API、DAS、身份和目录基础上建立最小指标、关系统计与证据模型 | 一个真实指标有固定时间依据、明确统计单位、去重/聚合规则及授权关系。    |
| 2    | 接入最小运行状态机、事件持久化、查询工具和对话闭环                | 两个权限不同的角色完成查询、澄清、追问和证据保存，覆盖权限与统计边界。 |
| 3    | 接入通用分析 Skill，使用真实案例迭代                              | 模型依据口径、目录和结果动态选择查询路径；计算可核对，结论可追溯。     |
| 4    | 完善历史报告、模板、画布和导出                                    | 模板按访问者权限执行，快照访问覆盖其完整数据范围。                     |

## 3. Data Access Service 第一版

### 3.1 服务骨架

- [ ] 创建独立、只读的 Data Access Service；查询请求无会话状态，模型不直接调用该服务。
- [ ] 建立 DAS 自己的 SQL Server 元数据与审计库，不与 `ai_bi_meta` 混用。
- [x] 在唯一的 `das.config.json` 中维护 API Host、内部端点、JWT 验签公钥文件路径、TLS 和 DAS 元数据 SQL Server 连接；密钥值只使用密钥系统或 `secret_ref`。
- [ ] 在 DAS 元数据 SQL Server 中持久化数据源连接配置、允许向 API 暴露的对象白名单和查询执行审计。
- [ ] DAS 启动后确保自身元数据表存在；开发阶段修改表结构时通过重建 DAS 元数据库应用变更。目标 SQL Server 数据库仍由部署预先创建。
- [ ] 支持内部传输方式和健康检查。
- [x] 首次注册校验 API 签发的实例接入凭证，后续每 30 秒携带随机会话发送 `dataAccessHeartbeatSchema`；成功心跳续期 90 秒。会话失效后重新注册，目录和查询调度同时核对健康记录与有效会话。（R-02，2026-09-13）
- [x] DAS 目录及五类管理入口校验 API 的短时请求 JWT；API 管理代理和诊断入口校验用户权限，系统管理员签发实例接入凭证。配置、停用与轮换见 [服务接入说明](../ai-data/SERVICE-AUTH.md)。（R-02，2026-09-13）
- [ ] 实现数据源适配层：健康检查、纯目录发现、查询校验和执行。
- [ ] 支持多个配置化数据源；MVP 先实现 SQL Server 连接器，并保留 HTTP API 连接器扩展点。
- [ ] HTTP API 连接器为每个数据源创建受控 Axios 实例，统一处理超时、请求/响应拦截、错误转换和取消；仅按 DAS 元数据中已审核的 JSONPath 响应映射提取、类型转换并输出统一扁平 Dataset。
- [ ] JSONPath 响应映射不能由 API、Agent 或用户请求传入，也不能出现在目录、查询结果或审计明细出口。
- [ ] SQL Server 连接器使用 `mssql` 建立连接池、超时、并发和连接回收。
- [ ] 从受保护配置读取 `secret_ref`，不向调用方返回连接信息。
- [ ] 业务数据库账号仅授予目标对象的只读权限；外部 API 使用受控只读凭据和出口配置。
- [ ] 确认 Data Access Service 不持久化业务数据、用户会话、查询结果和 API 原始权限策略；查询执行与拒绝事件写入 DAS 自己的 SQL Server 审计库。

### 3.2 访问上下文

- [x] 使用 `jose` 实现 API 到 Data Access Service 的短时 JWT；API 使用私钥签发，Data Access Service 使用公钥验签。
- [ ] JWT 通过 `Authorization: Bearer <token>` 请求头传递；模型工具只调用 API，Data Access Service 仅接收 API 构建的内部请求。
- [x] JWT 包含 `iss`、`aud`、`iat`、`nbf`、`exp`、`jti`、`analysis_run_id`、`policy_version`；有效期保持短时。
- [x] Data Access Service 在执行前校验 JWT 签名、签发方、接收方和有效期，并按东八区检查 `access.expires_at`；验收见 [R-03](./implementation-review.md#r-03-授权有效期和-jwt-必需字段校验不完整)。
- [ ] API 根据当前身份校验数据源、对象、字段、Join、参数、统计规则与行条件，按关联语义确定条件位置并生成最终可执行 DSL。
- [x] API 按每个别名将行授权和对象业务条件合并到 `from.filters` / `joins[].filters`；DAS 在对象参与连接前过滤，LEFT/RIGHT JOIN 保留语义不变，关联后的业务筛选写入 `query.filters`。（R-09 查询条件部分、R-13）
- [x] 关系查询行策略支持七种操作符、可信上下文白名单求值、允许范围 OR 与强制范围 AND；已配置策略缺少所需上下文或条件无法验证时明确拒绝，获准角色未配置行策略时允许完整对象范围。Join 必须完整匹配一条批准关系。（R-14、R-16）
- [x] API 为参数化数据集配置权限范围到受控参数的绑定，强制计算和校验参数；当前支持 `eq/in` 条件与标量等值参数，无法表达时拒绝查询。
- [x] API 校验参数化数据集的完整固定返回列满足列权限，生成脱敏规则，并签名 `expected_output` 交 DAS 核对；无法保证列权限时拒绝执行。
- [ ] API 在 `access.output_masks` 中写入结果列的 `partial_mask` 规则。
- [ ] API 构建 `{ access, query, signature }`；`signature` 覆盖前两项。
- [ ] Data Access Service 验证 JWT、整体签名、过期时间、策略版本、本地数据源和对象白名单。
- [ ] 禁止 Agent 或前端通过工具参数覆盖用户、角色和组织身份。
- [ ] 明确多角色合并规则：显式拒绝优先，授权对象按规则合并。
- [ ] 对无对象授权、无效策略和策略加载失败默认拒绝。
- [ ] API 与 Data Access Service 使用内部 HTTP；每次请求校验 JWT 与整体签名。
- [ ] （后置）确定签名算法、重放防护和密钥配置完整性方案。

### 3.3 纯目录发现与返回

- [ ] 返回对象和字段的源注释、标准化类型、可空性、新鲜度、基础查询能力与输入参数。
- [ ] Data Access Service 只返回连接器发现的纯数据源结构，不返回敏感等级，也不自行推断敏感字段或脱敏策略。
- [ ] HTTP API 数据集目录和查询结果只返回映射后的统一表结构，不返回原始 JSON、JSONPath、外部 URL 或接口密钥。

### 3.4 查询执行与编译器

- [ ] 根据 `source_id` 选择受保护的数据源配置，映射本地对象白名单并收紧运行限制。
- [ ] 校验对象、字段、别名、聚合、Join、排序、参数和限制能够被连接器编译。
- [ ] DAS 按 API 最终 DSL 的聚合、关联和条件位置执行，物理映射与资源限制保持查询语义。
- [x] 在查询结果出口按 `access.output_masks` 应用 `partial_mask` 规则；零长度与短值边界验收见 [R-01](./implementation-review.md#r-01-部分脱敏在末尾保留-0-位时泄露原文)。
- [ ] 拒绝自由 SQL、写操作、未允许函数、未授权对象和超限查询。
- [x] 强制最大返回行数，按数据源限制超时、并发与排队，并将取消传播到底层工作；名额在资源实际清理后释放。真实数据库专项待实跑。
- [x] 查询执行与拒绝链接入 DAS 审计仓储，验签后关联可信身份，审计失败时不返回结果；真实 SQL Server 写入待实跑。
- [ ] 返回结果、列元数据、新鲜度和截断状态；不返回连接器内部配置。
- [x] 按驱动元数据和 HTTP 字段声明标准化结果值，拒绝不可转换值及 HTTP 非空约束违反；数据库兼容性待真实环境验收。（R-06）
- [x] 公共查询结果与 DAS 共用列名、行字段、单元格类型和行数校验，SSE 事件严格校验并复用表格合同。（R-10）
- [x] API/DAS 交付有界完整结果，落实行数、结果字节和时间预算，在结果合同中保留完整性、实际行数及截断语义；DAS 31 项 SQL Server 集成通过，验收范围见[专项设计](./result-delivery-and-export.md#85-本轮验收记录2026-09-14)。
- [x] API 结果交付与运行幂等、权限复查、5,000 行/2 MiB 证据容量和 100 行/256 KiB SSE 表格样本衔接；API 327 项单元及 12 项 SQL Server 业务集成通过，浏览器完整结果状态按第 6.2 节实施。
