## 请求信息

| 方法与路径                       | 输入                                | 成功响应                              | 权限                        |
| -------------------------------- | ----------------------------------- | ------------------------------------- | --------------------------- |
| POST /auth/login                 | username、password                  | 200，令牌及用户摘要                   | 本地有效账号                |
| POST /auth/refresh               | refresh_token 可选；省略时读 Cookie | 200，与登录相同，并轮换 Refresh Token | 有效刷新令牌                |
| POST /auth/logout                | 无请求体                            | 204                                   | Access Token                |
| GET /auth/me                     | 无                                  | 200，当前身份上下文                   | Access Token                |
| POST /admin/users                | 创建用户字段，见下表                | 201，用户公开资料                     | system_admin 或 user:manage |
| GET /admin/users                 | 无                                  | 200，`{ items }`                      | 同上                        |
| GET /admin/users/:id             | 路径 id                             | 200，用户公开资料                     | 同组织管理权限              |
| POST /admin/users/:id/enable     | 路径 id                             | 204                                   | 同上                        |
| POST /admin/users/:id/disable    | 路径 id                             | 204                                   | 同上                        |
| PUT /admin/users/:id/departments | department_ids 字符串数组           | 204                                   | 同上                        |

## 请求参数

登录的 `username`、`password` 为必填非空字符串。刷新体为严格对象，`refresh_token` 为可选非空字符串。

| 创建用户字段             | 类型     | 必填 | 默认值与约束            |
| ------------------------ | -------- | ---- | ----------------------- |
| username                 | string   | 是   | 非空                    |
| display_name             | string   | 是   | 非空                    |
| password                 | string   | 是   | 至少 8 个字符           |
| role_ids                 | string[] | 否   | []，角色 ID             |
| exception_data_scope_ids | string[] | 否   | []，用户例外数据范围 ID |

组织由当前管理员身份决定。部门集合为空表示收回该用户的部门范围；相关行策略会在范围为空时拒绝查询。

## 请求与响应示例

```http
POST /auth/login
Content-Type: application/json

{"username":"example-user","password":"<PASSWORD>"}
```

```json
{
  "accessToken": "<ACCESS_TOKEN>",
  "refreshToken": "<REFRESH_TOKEN>",
  "expiresIn": 900,
  "user": {
    "id": "user-001",
    "organizationId": "org-001",
    "username": "example-user",
    "displayName": "示例用户"
  }
}
```

`expiresIn` 为实际配置的 Access JWT 秒数。刷新令牌同时通过 `refresh_token` HttpOnly Cookie 设置，路径为 `/auth`，SameSite=Lax；生产环境启用 Secure。退出撤销服务端会话并清空 Cookie。

`GET /auth/me` 返回 `userId、organizationId、sessionId、roles、roleIds、permissions、dataPolicies、permissionContext`；后两项为当前授权资料，`roleIds` 和 `permissionContext` 可省略。

管理员用户响应为 `id、organization_id、username、display_name、status、authorization_version`，其中 `status` 为 `active/disabled/pending`。状态和部门变更递增授权版本。

## 失败与约定

账号、密码或刷新会话无效返回 `401 AUTHENTICATION_FAILED`；管理权限不足为 `403 UNAUTHORIZED`；用户不存在或不属于当前组织为 `404 NOT_FOUND`；输入校验失败为 `400 INVALID_INPUT`。完整错误结构见[接口约定](/api/intro)。

## 部门集合约束

`department_ids` 最多 1000 项，每项去除首尾空白后长度为 1–128 字符，标识不得重复。
