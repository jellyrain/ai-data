## 请求信息

`POST /query` 使用用户 Access Token，正文直接为 QueryDsl。成功为 `200` 和 QueryResult，并设置 `Cache-Control: no-store`。API 负责填充访问范围、签名和内部 JWT。

## 关系查询示例

```http
POST /query
Authorization: Bearer <ACCESS_TOKEN>
Content-Type: application/json

{
  "type": "relational_query",
  "source_id": "clinical",
  "from": {"object_id":"visits","alias":"v"},
  "select": [
    {"field":"v.department","as":"department"},
    {"field":"v.id","aggregation":"count_distinct","as":"visits"}
  ],
  "group_by": ["v.department"],
  "limit": 100
}
```

示例对象和字段为虚构值，替换为[授权目录](/api/catalog)中的名称。参数化查询使用 `type: parameterized_query`，完整结构见下方字段参考，配置方式见[参数化数据集](/develop/parameterized-queries)。

## 成功响应与完整性

响应包含 `columns、rows、row_count、truncated`，可选 `freshness`；API 补充 `delivery`。`delivery.status` 为 `complete/truncated`，完整时 `total_row_count` 等于已返回行数，截断时为 null。列定义及可选关联字段见下方参考。

普通查询硬上限为 100,000 行和 32 MiB，实际还受数据源更小的 row_limit 约束。运行证据最多 5,000 行 / 2 MiB，模型工具最多取 100 行并受 32 KiB 样本预算限制。客户端应同时展示行数和完整性。

## 失败与取消

未授权对象和列分别为 `403 UNAUTHORIZED_OBJECT/UNAUTHORIZED_COLUMN`；权限条件无法表达或查询期间权限变化为 `403 POLICY_REJECTED`；查询能力、范围超限为 `400 UNSUPPORTED_QUERY/QUERY_LIMIT_EXCEEDED`；超时为 `504 QUERY_TIMEOUT`，数据源不可用为 `503 DATA_SOURCE_UNAVAILABLE`。客户端断开会触发本次 HTTP 查询取消。
