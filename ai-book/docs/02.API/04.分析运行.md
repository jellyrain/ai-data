## 请求信息

所有接口使用 Access Token，并校验所属用户和组织；路径 `id` 为 1–128 字符的运行 ID。

| 方法与路径                       | 输入                     | 200 响应                               |
| -------------------------------- | ------------------------ | -------------------------------------- |
| GET /analysis-runs/:id           | 路径 ID                  | 当前运行快照                           |
| GET /analysis-runs/:id/evidence  | 路径 ID                  | `{ items: 查询证据[] }`                |
| GET /analysis-runs/:id/steps     | 路径 ID                  | `{ items: 执行步骤[] }`                |
| POST /analysis-runs/:id/answers  | 澄清回答                 | 更新后的运行快照                       |
| POST /analysis-runs/:id/cancel   | 无请求体                 | 运行快照                               |
| POST /analysis-runs/:id/queries  | idempotency_key、query   | 查询证据                               |
| GET /analysis-runs/:id/events    | Last-Event-ID 请求头可选 | SSE 流                                 |
| GET /analysis-runs/:id/artifacts | 路径 ID                  | `{ items: [{ artifact_id, report }] }` |

## 回答澄清

```http
POST /analysis-runs/run-001/answers
Authorization: Bearer <ACCESS_TOKEN>
Content-Type: application/json

{"clarification_id":"question-001","idempotency_key":"answer-001","option_id":"current-month"}
```

`option_id` 与 `custom_input` 二选一，且问题必须是当前待答问题。自定义文本最多 8000 字符；各 ID 与幂等键最多 128 字符。偏好确认使用绑定问题的 `approve/reject` 选项。成功后同一运行重新进入待执行状态。

## 运行快照

`analysis_run_id、conversation_id、organization_id、user_id` 标识归属；`status` 是当前状态；`sequence` 是已持久化事件序号；`clarification` 为待答问题或 null；`evidence_ids` 为证据引用；`error` 为错误对象或 null。`agent_id` 与 `agent_version` 成对出现，表示实际绑定版本。完整字段见下方数据结构。

`created → running → completed` 为一般流程；澄清进入 `waiting_clarification`，回答后回到 `created`；取消经过 `cancelling/cancelled`，失败进入 `failed`。终态不会被迟到结果覆盖。

## 行为和失败

证据查询复用同键结果；查询前和交付前检查当前权限。取消作用于指定运行，关闭 SSE 连接仅停止订阅。跨用户不可读取运行，旧问题回答、冲突输入或非法状态转换会被拒绝；使用 `400 INVALID_INPUT、403 UNAUTHORIZED/POLICY_REJECTED、404 NOT_FOUND、409 CONFLICT/CANCELLED` 等[稳定错误](/api/intro)判断。
