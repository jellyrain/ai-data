## 接入与诊断

| 方法与路径                                             | 认证和输入                                       | 200 响应                                                 |
| ------------------------------------------------------ | ------------------------------------------------ | -------------------------------------------------------- |
| POST /admin/data-access/services/:serviceId/credential | 管理员 Access Token；system_admin；无请求体      | `{ service_id, credential }`，Cache-Control: no-store    |
| GET /internal/data-access/services                     | Access Token；system_admin 或 data-access:manage | `{ items }`，当前会话有效的健康实例                      |
| GET /internal/data-access/catalog/:sourceId            | 同上；路径为 source_id                           | `{ source_id, service_id, items }`                       |
| POST /internal/data-access/register                    | Bearer 实例接入凭证；DataAccessHeartbeat         | `{ service_id, session_token, session_timeout_seconds }` |
| POST /internal/data-access/heartbeat                   | Bearer 运行期会话凭据；DataAccessHeartbeat       | `{ service_id, accepted_at }`                            |

健康实例条目包含 `service_id、service_url、service_version、status、last_heartbeat_at、sources`。字段结构见[DAS 字段](/api/structures/das)，接入过程见[DAS 接入](/deployment/das-registration)。

```http
POST /admin/data-access/services/data-access-service/credential
Authorization: Bearer <ACCESS_TOKEN>
```

```json
{
  "service_id": "data-access-service",
  "credential": "<REGISTRATION_CREDENTIAL>"
}
```

## 数据源管理代理

以下路径前缀为 `/admin/data-access/services/:serviceId`，使用 Access Token，要求 `system_admin` 或 `data-access:manage`。成功均为 `200`。

| 方法与后缀                         | 请求结构                                                         | 响应                                                       |
| ---------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| POST /data-source-secrets          | secret_ref、connector_kind、host、port、user、password           | `{ secret_ref }`                                           |
| POST /database-targets             | secret_ref、connector_kind；Oracle 目标可选字段                  | `{ databases: [{ name, connect_target, connect_type? }] }` |
| PUT /data-sources                  | 单库数据源配置                                                   | `{ source_id }`                                            |
| POST /data-source-objects/discover | `{ source_id }`                                                  | `{ items: ManageableSourceObject[] }`                      |
| PUT /data-source-objects           | `{ source_id, objects: [{ object_id, procedure_definition? }] }` | `{ source_id, object_count }`                              |

保存连接凭据示例：

```json
{
  "secret_ref": "clinical-reader",
  "connector_kind": "sqlserver",
  "host": "db.example.internal",
  "port": 1433,
  "user": "readonly_user",
  "password": "<DATABASE_PASSWORD>"
}
```

保存单库数据源示例：

```json
{
  "source_id": "clinical",
  "connector_kind": "sqlserver",
  "secret_ref": "clinical-reader",
  "target_database": "ClinicalExample",
  "timeout_ms": 10000,
  "connection_pool_limit": 10,
  "concurrency_limit": 10,
  "row_limit": 5000
}
```

`connector_kind` 接受 `sqlserver/mysql/postgresql/oracle`。前三种使用 `target_database`；Oracle 使用成对的 `oracle_connect_type` 与 `oracle_connect_target`。Oracle 数据库实机专项仍待验证。`is_enabled` 默认 true，`row_limit` 最大 100000。所有默认值和限制见[DAS 字段](/api/structures/das)。

对象白名单按完整列表替换，空数组清空该源暴露对象。存储过程需完整签名配置；[参数化数据集](/develop/parameterized-queries)说明其执行与权限限制。

## DAS 内部入口

这些路径相对于 DAS 地址，供 API 服务端调用。API 将管理操作转为同名的 `/internal/admin/...` 路径，并签发绑定服务、用途、HTTP 方法、路径及正文摘要的短时 JWT。

| 方法与路径                                        | 输入                           | 响应                                       |
| ------------------------------------------------- | ------------------------------ | ------------------------------------------ |
| POST /internal/catalog                            | `{ source_id }`                | 200，`{ items: Dataset[] }`                |
| POST /internal/query                              | `{ access, query, signature }` | 200，QueryResult                           |
| POST /internal/admin/data-source-secrets          | 共享数据库凭据                 | 200，`{ secret_ref }`                      |
| POST /internal/admin/database-targets             | 目标发现请求                   | 200，`{ databases }`                       |
| PUT /internal/admin/data-sources                  | 单库数据源配置                 | 200，`{ source_id }`                       |
| POST /internal/admin/data-source-objects/discover | `{ source_id }`                | 200，`{ items: ManageableSourceObject[] }` |
| PUT /internal/admin/data-source-objects           | 完整对象白名单                 | 200，`{ source_id, object_count }`         |

目录和管理使用对应服务 JWT；查询另校验 access 与最终 query 的整体签名和过期时间。内部查询返回 `x-request-id`。调用方应通过[业务查询](/api/query)获得授权结果。

## 失败与重试

用户管理权限不足为 `403 UNAUTHORIZED`；实例会话无效或源不可用为 `503 DATA_SOURCE_UNAVAILABLE`；凭证不匹配为 `401 AUTHENTICATION_FAILED`；格式或管理业务请求不能完成时为 `400 INVALID_INPUT`。有效期内相同管理请求可能重复提交，当前管理代理不提供统一幂等去重。

## 发现对象响应

items 条目包含 `object_id、kind、native_object_name、columns`，可选 `native_schema_name、source_description`。选择白名单时使用发现返回的 object_id；服务保存前会重新核对当前目录。
