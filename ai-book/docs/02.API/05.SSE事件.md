## 连接与恢复

`GET /analysis-runs/:id/events` 使用 `Authorization: Bearer <ACCESS_TOKEN>`，响应 `Content-Type: text/event-stream; charset=utf-8`。浏览器接入需使用可携带认证头的流式请求方式。

`Last-Event-ID` 为运行内已处理序号，十进制整数范围 0–2147483647，省略为 0。大于当前运行序号返回 `400 INVALID_INPUT`。恢复时按序推送该序号之后的持久化事件，客户端按序号去重。

```text
id: 1
event: run_started
data: {"type":"run_started","conversation_id":"conversation-001","analysis_run_id":"run-001","sequence":1}

: keep-alive

```

每个事件由空行结束，注释心跳不改变事件序号。`data` 是完整事件对象。

## 公共字段

| 字段            | 类型     | 必填 | 用途                      |
| --------------- | -------- | ---- | ------------------------- |
| type            | string   | 是   | 事件名称，与 event 行一致 |
| conversation_id | string   | 是   | 会话归属                  |
| analysis_run_id | string   | 是   | 本轮运行                  |
| sequence        | 非负整数 | 是   | 运行内事件序号            |
| lease_epoch     | 非负整数 | 否   | 本次执行租约代次          |

## 事件载荷

| 事件                                        | 额外字段                                                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| run_started / run_completed / run_cancelled | 无                                                                                                          |
| run_state                                   | status                                                                                                      |
| progress                                    | message                                                                                                     |
| thinking                                    | stage: understanding/planning/querying/validating/summarizing；content                                      |
| tool_call                                   | tool_name、input_summary；tool_call_id 可选                                                                 |
| tool_result                                 | tool_name、success、output_summary；tool_call_id 可选                                                       |
| clarification                               | question、options: [`{ id, label }`]、allow_custom_input；clarification_id、preference_confirmation_id 可选 |
| clarification_answered                      | clarification_id；option_id/custom_input 二选一                                                             |
| context_compaction                          | item_id、status: started/completed、occurred_at                                                             |
| final_answer                                | content                                                                                                     |
| table                                       | columns、rows；evidence_id、result_row_count、result_truncated、sampled 可选                                |
| chart                                       | chart_type: line/bar/pie/table；spec                                                                        |
| run_failed                                  | code、message                                                                                               |

## 终止与异常

服务持续复查当前身份；`completed/failed/cancelled` 终态且全部事件发送后结束流。澄清等待仍可保留连接。建立流前的认证和输入错误使用标准 JSON 错误；流建立后发生异常可能表现为断开，客户端重连前应读取运行快照和验证登录状态。

`final_answer` 表示答复内容，最终状态以运行快照和终态事件为准。上下文压缩提示在完成、运行终止、澄清等待或代次变化时结束。

## 结果完整性

`result_row_count` 表示原结果交付到 API 的行数，`sampled` 表示当前事件是否为部分样本，`result_truncated` 表示原查询是否已截断。SSE 表格最多 100 行 / 256 KiB，不能把样本行数当作完整业务总数。
