第 9 步，2026-09-21。供 API 调用方及后续 Web 接入使用。共享合同从 `@ai-data/contracts` 导入，所有接口使用当前登录身份；组织、作者与权限由服务端确定。

## 同一份定义与三个版本标识

对话、参数表单与画布共同编辑 `ReportDefinition`，通过公共保存服务形成同一 `report_id` 的连续版本。定义包含 `parameters`、`queries`、`presentation`、`block_references` 和可选 `editor_layout`。画布坐标只影响编辑展示；关系边、筛选和聚合保存在查询项中。

| 标识               | 含义                                   | 使用位置                                                   |
| ------------------ | -------------------------------------- | ---------------------------------------------------------- |
| 定义记录 `version` | 参数、查询和展示的版本                 | 更新时传 `expected_version`，执行时传 `definition_version` |
| `execution_id`     | 某人按固定版本和实际参数发起的一次执行 | 读取结果、生成说明和执行导出                               |
| 快照记录 `version` | 同一报表累计保存的结果快照版本         | `GET /reports/:id?version=N`；与定义版本独立递增           |

执行记录固定定义、实际参数、逐项证据和结果快照。快照另外记录 `definition_version` 与 `execution_id`。保存定义不查询业务数据；修改后由调用方显式运行。历史执行继续引用原定义与参数。

## 定义、结果与管理接口

| 方法与路径                                              | 输入或用途                                                                              |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `POST /report-definitions`                              | 创建定义：`{ definition, shared_with?, source_analysis_run_id?, source_artifact_id? }`  |
| `GET /reports/:id/definition?version=N`                 | 返回指定或当前可访问定义                                                                |
| `PUT /reports/:id/definition`                           | 完整定义及 `expected_version`；成功保存下一版                                           |
| `GET /reports?limit=20&cursor=ID`                       | 当前可访问摘要；最多 100 条，使用响应的 `next_cursor` 翻页                              |
| `GET /reports/:id/versions`                             | `{ definitions, snapshots }` 两条版本序列                                               |
| `PUT /reports/:id/sharing`                              | `{ expected_version, shared_with: [用户ID] }`；仅作者，接收者须为本组织有效用户         |
| `POST /reports/:id/execute`                             | 固定定义版本、实际参数和幂等键                                                          |
| `GET /report-executions/:id`                            | 当前执行状态及已完成结果                                                                |
| `POST /reports/:id/revisions`                           | 发起绑定目标与版本的对话编辑，返回 202 和运行回执                                       |
| `POST /report-executions/:id/narratives`                | 基于指定已完成执行生成分析说明，返回 202                                                |
| `GET /report-executions/:id/narratives`                 | `{ items }`，只包含该次执行的说明                                                       |
| `GET /analysis-runs/:id/artifacts`                      | 已完成运行的 `{ items: [{ artifact_id, report }] }`                                     |
| `POST /reports`、`GET /reports/:id`、`PUT /reports/:id` | 兼容原结果快照接口；创建输入为 `SaveReportInput`，更新为 `{ expected_version, report }` |

定义更新提交完整内容；保留现有分享名单时需一并提交 `shared_with`。省略该字段按合同默认空数组处理。分享修改也形成新定义版本，因此下一次编辑需要使用返回的新版本。

快照和产物的公开读取要求来源运行已完成，逐份重新检查当前对象、字段、行范围与脱敏规则。最新分享名单控制旧版本访问。旧结果范围无法被访问者完整覆盖时拒绝读取；访问者可以按自己的当前权限运行其可访问的定义。

## 创建、追加参数与执行示例

以下名称为虚构目录标识，需换为当前目录实际授权的对象与字段。

创建 `POST /report-definitions`：

```json
{
  "definition": {
    "title": "科室就诊人次",
    "parameters": [
      {
        "name": "department",
        "label": "科室",
        "data_type": "string",
        "required": false
      }
    ],
    "queries": [
      {
        "query_id": "visits",
        "query": {
          "type": "relational_query",
          "source_id": "clinical",
          "from": { "object_id": "visits", "alias": "v" },
          "select": [
            { "field": "v.department", "as": "department" },
            { "field": "v.id", "aggregation": "count_distinct", "as": "visits" }
          ],
          "group_by": ["v.department"]
        },
        "bindings": [
          {
            "parameter": "department",
            "target": {
              "type": "filter",
              "scope": "query",
              "field": "v.department",
              "op": "eq"
            }
          }
        ]
      }
    ],
    "presentation": [
      {
        "section_id": "main",
        "title": "统计结果",
        "blocks": [
          {
            "block_id": "table",
            "type": "table",
            "title": "人次",
            "query_ids": ["visits"]
          },
          {
            "block_id": "chart",
            "type": "chart",
            "title": "科室分布",
            "query_ids": ["visits"],
            "chart": { "type": "bar", "x": "department", "y": "visits" }
          }
        ]
      }
    ]
  },
  "shared_with": []
}
```

读取返回的 `report_id` 和 `version`。二次编辑在原定义中增加参数与对应 `bindings`，连同当前 `expected_version` 提交 `PUT /reports/:id/definition`。参数改名或删除时同步更新绑定和块映射；引用缺失、类型不符、重复标识、无效字段及旧版本冲突均拒绝保存。

执行 `POST /reports/:id/execute`：

```json
{
  "definition_version": 2,
  "idempotency_key": "visits-september-A-1",
  "parameters": { "department": "A" }
}
```

接口返回 `ReportExecution`。实际查询在此次请求内执行；相同键的并发请求可以读到 `running`，随后通过执行 ID 读取。键在组织、用户与报表范围内唯一。同键且相同请求复用记录；同键修改版本或参数返回 `CONFLICT`。失败或过期的记录保持终态，显式重跑使用新键。

保存有权限的定义并不授予额外数据权限。每个查询项经过当前授权和 DAS 签名执行；两个展示块引用同一 `query_id` 时只执行一次。多个查询项分别产生结果，通过 `results[].query_id` 对应表格与图表。

## 参数和查询图

参数支持 `required`、`default_value`、`allowed_values`、`min`、`max`。类型复用共享数据类型；参数值为标量或有界数组。未提供的可选参数省略其绑定条件；必填参数缺失拒绝执行。`between` 需要两个值，`in`/`not_in` 使用数组，仍受原查询合同校验。

相对日期在每次执行时按东八区重新解析，执行记录保存实际日期。例如：

```json
{
  "name": "start",
  "label": "开始日期",
  "data_type": "date",
  "relative_time": {
    "range": { "type": "relative", "period": "this_year" },
    "part": "start"
  }
}
```

固定默认值与相对时间默认值互斥。日期使用 `YYYY-MM-DD`，日期时间使用 `YYYY-MM-DD HH:mm:ss`。

| 绑定目标      | 字段                       | 用途                                                |
| ------------- | -------------------------- | --------------------------------------------------- |
| `filter`      | `field, op, scope, alias?` | `scope` 为 `query/from/join/on`；后两者填写连接别名 |
| `parameter`   | `name`                     | 参数化数据集的命名输入，执行时继续校验强制权限参数  |
| `metric_date` | `part: start/end`          | 指标日期；统计口径由已发布指标定义控制              |

参数替换同一位置的固定字段与操作符筛选时保留原布尔组，追加条件采用外层 AND。客户端不能通过参数值替换对象、字段、关系或服务端行权限。

关系查询复用现有投影、筛选、分组、排序、去重与预聚合合同。图中的连接声明如下，完整 `on` 字段对由服务端按当前批准关系构建：

```json
{
  "type": "left",
  "object_id": "departments",
  "alias": "d",
  "source_alias": "v",
  "relation_id": "visit_department"
}
```

`source_alias` 必须是前面已有对象，关系方向和连接方式必须获准。同表多别名、多字段关系均沿用此模型。`editor_layout.nodes` 保存 `{ id, x, y }`；Web 将画布节点和边映射到上述统一查询图后提交同一保存接口。

指标查询使用 `{ type: "metric_query", metric_id, version?, output: "grouped" | "total", start, end, dimensions }`。分组和总计为独立查询项；同次执行对同一版本选择固定实际指标版本，证据记录该版本。总计使用指标原口径独立重算。历史指标快照提取时，仅在发布口径能够精确重建原请求时恢复固定指标引用。

## 对话编辑和分析说明

编辑请求：

```json
{
  "expected_version": 2,
  "idempotency_key": "append-department-1",
  "prompt": "把科室加成筛选参数，保留现在的日期条件"
}
```

可选 `agent_id` 选择有效 Agent。服务端绑定目标报表和基准版本，模型使用 `get_report_definition` 与 `save_report_definition`，结构化修改先暂存。运行成功完成时，在完成事务中调用公共定义保存服务；版本冲突、取消、失败及失效租约不提交新定义。运行状态、事件、澄清和取消继续使用现有分析运行接口。

普通对话也可以通过 `save_report_definition` 创建定义。已有 `save_report` 工具继续保存带证据的快照，并在成功完成事务中转换出同 ID 的可编辑定义。手动保存已完成分析的快照同样原子创建定义。

说明请求为 `{ prompt, idempotency_key, agent_id? }`，提交到指定执行的 `/narratives`。说明运行只允许读取绑定执行结果、读取 Skill 参考文档及发起澄清；最终内容和查询引用存入该执行。新一次参数运行保留旧说明的历史归属，新结果需要另行生成说明。模型读取的是有完整性标记的结果样本，业务结论仍需按证据及业务规则核对。

新 Agent 配置应包含 `get_report_definition`、`save_report_definition`、`get_report_execution`。已保存 Agent 版本及已有会话继续使用其固定工具白名单；需要新能力时发布新的 Agent 版本，并用该版本发起编辑或说明。直接运行已保存报表无需模型参与。

## 可复用块与组织模板

块使用与报表相同的完整定义合同。`POST /report-blocks` 创建，`GET /report-blocks` 分页，`GET /report-blocks/:id?version=N` 读取，`PUT /report-blocks/:id` 携带 `expected_version` 更新。保存块必须填写已完成且属于当前用户的 `source_analysis_run_id`，可以同时指定该运行的 `source_artifact_id`。

引用块时将查询和参数展开到当前定义，并填写 `block_references: [{ block_id, version, query_id_map, parameter_map }]`。映射必须覆盖固定块版本的全部查询与参数，服务校验展开内容一致。块更新后，由引用方明确选择新版本并保存报表；历史版本引用保持固定。

组织模板通过现有知识审核链发布。提交 `POST /knowledge-candidates`：

```json
{
  "idempotency_key": "publish-visits-2",
  "content": {
    "type": "report_template",
    "report_id": "example-report-id",
    "definition_version": 2,
    "definition_hash": "替换为64位小写十六进制摘要"
  },
  "scope": { "source_id": "clinical" }
}
```

摘要为返回定义的 `sha256(stableStringify(record.definition))`；`stableStringify` 从共享合同导入。作者或知识维护者可以提交候选；负责人指派、审核、发布时间、启停和回滚沿用[知识接口](/admin/knowledge-memory)。审核固定版本和摘要，修改定义后需提交对应的新候选。发布回滚生成新的知识发布版本，并引用原固定定义。

`GET /report-templates` 返回 `{ items: ReportDefinitionVersion[] }`，仅包含当前身份可用的已生效发布版本。知识发布 ID、版本及生效时间从 `/knowledge` 的 `report_template` 内容关联读取。私有新定义不进入组织模板目录；模板授权不覆盖原始结果的数据权限。

## 目录关系发布

| 路径                                                       | 用途                                         |
| ---------------------------------------------------------- | -------------------------------------------- |
| `GET /catalog/:sourceId/objects/:objectId/relations`       | 当前可见对象及字段范围内的一层入向、出向关系 |
| `GET /admin/catalog/:sourceId/objects/:objectId/relations` | 管理完整关系记录，包含启停状态               |
| `POST /admin/catalog/:sourceId/relations/publish`          | `{ changes: [...] }` 原子批量发布            |

每个变更声明 `create/update/disable`。创建或更新提供 `object_id` 和 `relation`，更新及停用提供当前 `expected_version`；停用提供 `relation_id`。关系包括稳定 ID、目标对象、完整字段对、基数和批准的连接方式。字段、类型、唯一键证明、关系基数及并发版本均经校验，任意项失败则整批回滚。批量发布未列出的旧关系保留。

现有数据集配置接口读写同一批关系记录，读取响应的 `x-config-version` 用于完整配置保存的 `expected_version`。完整配置保存按提交列表替换该对象的关系；入向关系仅供图浏览，不产生隐式反向执行权。

## 执行预算与导出内容

单项证据及整次执行合计均最多 5,000 行、2 MiB。默认整次执行时限 120 秒，执行租约定期续期。多查询失败、超预算、过期或交付前权限变化时整体失败，完成快照不会部分提交。失败结果通过 `status: "failed"` 和 `error_code` 表达；输入、访问及幂等冲突走统一 API 错误响应。读取过期 `running` 执行时收敛为失败，迟到结果不能覆盖终态。

| 路径                                        | 返回合同                                              |
| ------------------------------------------- | ----------------------------------------------------- |
| `GET /reports/:id/export-content?version=N` | `{ kind: "report", report, tables }`                  |
| `GET /report-executions/:id/export-content` | `{ kind: "report_execution", execution, narratives }` |
| `GET /conversations/:id/export-content`     | 会话标题、按序用户/助手消息、运行状态、产物及证据表格 |

内容读取全部来自持久化结果，先复核当前权限，不新增业务查询。报告与会话表格标注 `availability: complete/truncated`；执行证据保留 `result.truncated` 等完整性字段。已保存且截断的结果只能导出已有范围。普通查询的 100,000 行、32 MiB 明细交付继续使用原查询接口。

Web 阶段按[交付设计](/manual/reports)实现详情页、参数表单、画布交互和 Excel、Word、PDF 文件生成，复用这些内容包和完整性标记。

## HTTP 响应与失败

所有接口使用用户 Access Token。创建定义、快照和块返回 201；对话编辑与说明返回 202 和 `{ conversation_id, analysis_run_id }`；其他成功操作返回 200。定义创建、读取和更新返回 ReportDefinitionVersion，块返回固定块版本，报表快照接口返回 SavedReport。列表使用 ReportList，含 items 与可选 next_cursor；版本集合包含 definitions 和 snapshots。

输入校验失败为 400 INVALID_INPUT，未启用对话时编辑/说明可返回 400 UNSUPPORTED_QUERY；作者或数据权限不足为 403 UNAUTHORIZED/POLICY_REJECTED；不可访问资源为 404 NOT_FOUND；旧版本、同键不同请求或未完成执行上生成说明为 409 CONFLICT。执行中的业务失败也可能以 HTTP 200、status: failed 和 error_code 返回，应同时检查状态。
