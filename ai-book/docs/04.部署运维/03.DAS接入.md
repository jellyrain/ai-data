API 负责用户授权与实例接入许可。DAS 的目录和管理接口使用 API 公钥验证请求；DAS 启动注册时提交 API 签发的实例接入凭证，随后用 API 返回的随机会话凭据发送心跳。

## 部署与首次接入

1. 在 API 的 `apps/api/config/api.config.json` 中配置获准实例，然后启动或重启 API。`service_id` 必须与 DAS 配置一致；未配置的实例不能接入。

   ```json
   {
     "trusted_data_access_services": [
       {
         "service_id": "data-access-service",
         "credential_version": 1,
         "enabled": true
       }
     ]
   }
   ```

2. 系统管理员登录 API 后，使用自己的 Access Token 调用 `POST /admin/data-access/services/data-access-service/credential`，请求头为 `Authorization: Bearer <管理员 Access Token>`。响应包含 `service_id` 和 `credential`，并设置 `Cache-Control: no-store`。把 `credential` 的字符串内容保存为 DAS 的 `apps/data-access/secrets/api-registration.jwt`，仅允许部署管理员与 DAS 服务账户读取。该文件所在目录已被 Git 忽略。
3. 将 API 的 `apps/api/secrets/jwt-public.pem` 部署到 DAS 可读取的位置。在 DAS 的 `apps/data-access/config/das.config.json` 中填写以下 `api` 配置。文件路径均相对于配置文件所在目录；同机开发示例的公钥路径直接指向 API 目录。

   ```json
   {
     "api": {
       "base_url": "http://127.0.0.1:3101",
       "registration_path": "/internal/data-access/register",
       "registration_credential_path": "../secrets/api-registration.jwt",
       "heartbeat_path": "/internal/data-access/heartbeat",
       "jwt_verification_public_key_path": "../../api/secrets/jwt-public.pem"
     }
   }
   ```

4. 启动 DAS。它先读取公钥与接入凭证文件，监听成功后提交首次健康快照。API 验证凭证的签名、来源、接收方、实例标识和凭证版本，通过后返回会话；系统管理员可读取 `GET /internal/data-access/services` 查看已注册的健康实例。

接入凭证的生命周期由 API 的实例启用状态和 `credential_version` 管理，签发时不设置自动过期时间。API 私钥保存在 API 本地；DAS 接入文件与运行期会话均具有持有者凭据的作用，需要保护文件权限及网络传输。

## 心跳与恢复

| 阶段       | 请求                                                                                             | API 校验与响应                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 首次接入   | `POST /internal/data-access/register`，Bearer 为实例接入凭证，正文为 `dataAccessHeartbeatSchema` | 验签并建立实例与地址绑定，返回 `service_id`、`session_token`、`session_timeout_seconds: 90` |
| 运行期心跳 | 每 30 秒调用 `POST /internal/data-access/heartbeat`，Bearer 为会话凭据                           | 校验会话、实例和地址，保存健康状态并续期 90 秒；返回 `service_id`、`accepted_at`            |
| 会话失效   | API 返回 HTTP 401                                                                                | DAS 重新读取接入凭证文件，注册成功后使用新会话                                              |

会话仅保存在 API 内存中，服务端保存随机凭据的 SHA-256 摘要。超过 90 秒没有成功心跳、重新注册或 API 重启后，旧会话失效；API 重启后的数据库健康记录需有新的有效注册会话才能参与调度。网络临时失败保留当前会话，下个周期继续尝试。

注册时使用 TCP 连接远端 IP、DAS 上报端口及实际监听协议生成地址。心跳只能更新这个绑定，地址改变需要重新注册。当前方案用于单个 API 进程；多副本部署需要共享会话存储或固定实例路由。反向代理与 NAT 必须保证 API 登记的地址能实际回调 DAS，当前不信任转发头推导实例地址。

同机示例使用回环 HTTP。跨主机部署需要受保护的加密链路，例如加密网络隧道；当前应用启动代码提供 HTTP 监听，TLS 终止及回调地址可达性由部署设施配置。HTTP 客户端禁止自动跟随重定向，避免将凭据发送到重定向目标。

## 停用与轮换

- 停用实例：将 API 对应配置的 `enabled` 设为 `false` 并重启 API。该实例的接入、心跳与查询调度都会被拒绝。
- 更换接入凭证：递增对应 `credential_version` 并重启 API。系统管理员领取新版本凭证并替换 DAS 文件；DAS 下次重新注册会读取新文件，旧版本凭证不再有效。
- 更换 API RSA 密钥：更新 API 密钥后，需要重新签发实例接入凭证，并更新 DAS 的公钥文件及重启 DAS。

## 目录与管理调用

用户通过 API 发起管理操作。系统管理员或拥有 `data-access:manage` 权限的用户可访问实例诊断、原始目录诊断及下列代理；领取接入凭证仅限 `system_admin`。

API 管理代理前缀为 `/admin/data-access/services/:serviceId`，目标地址从当前健康且会话有效的注册实例中选择。

| 方法 | 代理后缀                        | DAS 端点                                       |
| ---- | ------------------------------- | ---------------------------------------------- |
| POST | `/data-source-secrets`          | `/internal/admin/data-source-secrets`          |
| POST | `/database-targets`             | `/internal/admin/database-targets`             |
| PUT  | `/data-sources`                 | `/internal/admin/data-sources`                 |
| POST | `/data-source-objects/discover` | `/internal/admin/data-source-objects/discover` |
| PUT  | `/data-source-objects`          | `/internal/admin/data-source-objects`          |

API 为目录和管理请求签发 60 秒 JWT，绑定目标 `service_id`、请求用途、HTTP 方法、路径及正文摘要。DAS 使用配置的 API 公钥在业务处理前校验；查询使用既有查询 JWT 与 `{ access, query, signature }` 合同。有效期内的相同请求仍可重复提交，管理操作的重放去重不属于当前实现。

## 在独立实例中保存接入文件

以下 PowerShell 命令在 DAS 实例根目录执行，API 地址及实例标识与配置保持一致。登录使用[快速上手](/guide/quickstart)得到的 `$headers`。

```powershell
$serviceId = 'data-access-service'
$credentialResult = Invoke-RestMethod "$apiBase/admin/data-access/services/$serviceId/credential" -Method Post -Headers $headers
New-Item -ItemType Directory -Force -Path 'secrets' | Out-Null
[IO.File]::WriteAllText((Join-Path (Get-Location) 'secrets/api-registration.jwt'), $credentialResult.credential)
```

把 API 实例的 `secrets/jwt-public.pem` 复制到 DAS 的 `secrets/api-public.pem`，并在 DAS 配置中设置 `jwt_verification_public_key_path: "../secrets/api-public.pem"`。源代码同机开发示例中的 `../../api/secrets/jwt-public.pem` 依赖源码目录布局，分机部署要改为 DAS 自己可读的文件路径。
