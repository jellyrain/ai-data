## 排查入口

先记录请求返回的 `request_id`、发生时间、服务实例和错误码，再检查对应服务日志。用 `/health` 检查存活、`/ready` 检查元数据库就绪状态，业务数据源状态通过 API 的 DAS 管理接口读取。

| 现象                        | 核对项                                     | 处理方向                                                                     |
| --------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------- |
| 启动提示配置未知字段        | 当前配置 Schema 与 JSON 内容               | 使用[配置参考](/deployment/configuration)，模型参数通过数据库接口发布        |
| DAS 注册返回 401            | service_id、启用状态、凭证版本、API 公钥   | 重新签发匹配版本凭证并检查公钥；详见[DAS 接入](/deployment/das-registration) |
| 已注册但 API 无法查询 DAS   | 回调 IP、端口、协议与网络路由              | API 按真实连接来源登记地址，检查 NAT/代理下可达性                            |
| 503 DATA_SOURCE_UNAVAILABLE | 注册会话、心跳及目标 source_id 健康        | 修复连接后等待心跳，再查询健康列表                                           |
| 查询被拒绝                  | 对象、字段、关系、行范围和部门范围         | 按当前用户权限核对请求；管理员角色也需正确业务授权                           |
| 会话创建提示 Agent 不存在   | 当前组织下的模型和 Agent 清单              | 先发布模型，再发布指定 Agent                                                 |
| 运行停在 created            | analysis_runtime.enabled、服务日志         | 启用自动调度并检查 SQL 队列                                                  |
| 模型装配失败                | 对应版本、密文主密钥、Skill 快照与官方状态 | 恢复匹配文件，固定版本目录应保持发布内容                                     |
| 409 CONFLICT                | 预期版本与幂等键                           | 重新读取当前版本；重跑使用新键                                               |
| 模型达到工具或时间预算      | 运行步骤、模型行为与 Agent limits          | 根据实际失败原因调优后重新验证                                               |
| 输出数量比预期少            | delivery、truncated、sampled 与行权限      | 区分原查询截断和模型/SSE 样本；调整查询范围                                  |
| 历史报告无权查看            | 最新分享名单及完整证据授权                 | 在当前允许范围重新执行可访问的定义                                           |

## 已知验证边界

当前平台、模型专项及 Web 进度见[完成状态](/guide/status)。排查结果应区分配置错误、服务故障与尚未完成的业务验证。
