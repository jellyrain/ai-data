## 模块职责与目录

所有命令在仓库中的 `ai-data/` pnpm 工作区执行。说明站点位于同级 `ai-book/`。

```text
ai-data/
  apps/api/              Fastify API、权限与分析调度
  apps/data-access/      数据源、DSL 编译、查询执行和审计
  packages/contracts/    Zod 合同及类型
  packages/metadata/     SQL Server 持久化与加密基础设施
  packages/domain/       领域能力
  packages/config/       共享配置
  packages/skills/       分析 Skill 源库
  scripts/               工程检查与发布脚本
```

当前 `apps/` 下有 API 和 data-access，Web 包待创建。根脚本中的 `dev:web` 是后续入口。

## 本地准备

使用 Node.js `>=24.19.0 <25`、pnpm `11.22.0`。依赖由操作者在工作区执行 `pnpm install --frozen-lockfile` 准备，保留平台可选依赖。复制各应用 `config/*.config.example.json`，填写各自元数据库配置；API 和 DAS 的接入顺序见[部署指南](/deployment/first-start)。

```powershell
# 在 ai-data/ 执行；两个服务分别使用一个终端
pnpm dev:api
pnpm dev:data-access
```

开发配置示例与发布配置示例的路径、TLS 和运行时开关可能不同。使用与当前运行方式匹配的示例，依据[配置参考](/deployment/configuration)填写。

## 开发边界

共享能力从包的公开入口导入。应用不能导入另一个应用的源码，共享包不能反向依赖应用。共享 Schema 和 TypeScript 类型分文件维护，公共出口为 `packages/contracts/src/index.ts`。输入、持久化读取和跨服务响应先校验再使用。

业务日期使用 dayjs，并明确东八区语义。源码与测试按业务模块分类，测试放在对应包 `tests/`。

## 验证与协作

新增行为先写业务场景和预期，再编写测试、确认目标行为失败、实现并回归。命令见[测试与验证](/develop/testing)。开发规范和需求继续以仓库 `需求文档/development-standards.md` 等文件为准。说明站点更新时机见[文档维护](/develop/documentation)。
