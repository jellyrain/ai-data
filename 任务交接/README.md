## 用户确定的协作规则

> 要做之前先给我清单，我审核后再做。
>
> 以后你有什么小巧思先问我然后再做，包括可能要开几个子代理。

1. 新工作先提交目的、影响范围、文件增删改、依赖操作和验证清单，取得明确批准后执行。
2. 已批准范围内持续完成；新增想法、架构变化、优化和扩大范围先审核。
3. 子代理必须先说明数量、分工和范围，并取得明确批准。已有代理也不能自动继续派工。
4. 依赖安装、升级和卸载由用户执行。验证直接使用已安装的 CLI，避免包管理器在执行命令时自动整理依赖。
5. 不兼容时说明实际问题；提出选择须逐项解释原因、影响和代价。未经批准不改技术路线。
6. Skill 中建议的额外工作也遵守上述范围和审批规则。不能把先前批准后的实现再次当作待审核提案。
7. 工作区存在大量既有未提交改动，保留现状和归属，不整批回退、清理或提交。
8. `ai-book` 仅在用户明确要求更新文档时按批准范围修改，覆盖说明、归档、首页和站点配置；日常开发、功能新增、接口调整和问题修复不自动触发更新。
