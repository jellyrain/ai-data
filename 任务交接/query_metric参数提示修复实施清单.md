# query_metric 参数提示修复实施清单

日期：2026-10-08。用户确认“可以”，批准上一轮列出的 API 工具参数说明、指标详情、错误提示及对应测试范围。主代理单独实施，依赖操作为 0。

## 已核实的问题

只读审计显示，当日 query_metric 15 次调用中 11 次为 INVALID_INPUT、4 次成功。门诊指标的 date_basis.data_type 为 datetime，近期失败包括只传日期、使用 T 分隔的时间、只传月份及混入其他文本。8 月科室排名两次使用相同日期参数失败，补齐空格分隔的时分秒后成功。

发给模型的 start/end Schema 仅显示字符串，未携带具体格式；指标服务把时间类型、未发布维度和重复维度合并成一个错误。参数格式错误在审计中只留通用提示。

## 改动范围

1. query_metric 参数定义说明 date/datetime 格式、东八区、起止边界及维度来源。
2. describe_metric 根据已授权指标定义返回 query_requirements，包含格式、合法维度与格式示例。
3. 指标服务分别报告时间类型不匹配、重复维度和未发布维度；工具参数错误的具体字段及格式同时进入模型返回和审计摘要。
4. 保持固定时间依据、严格参数校验和已发布维度约束，时间值按调用方明确提供的范围执行。

预计修改 API 的 runtime/tool-contracts.ts、runtime/analysis-tools.ts、metrics/metric-service.ts，新增指标调用要求辅助模块；新增或补充 runtime、metrics 对应测试。整理 API 构建产物，在任务交接保存交付说明、流程图和验证结果，并追加 README。

## BDD 验收场景

- 模型读取工具定义时，可以看到 start/end 的合法格式与维度来源。
- date 和 datetime 指标的 describe_metric 分别返回对应格式、固定时间字段、合法维度和能通过实际合同的示例；指标无可用维度时示例使用空数组。
- datetime 指标接收仅日期时指出 start 或 end 所需格式；date 指标接收时分秒时指出日期格式。
- ISO T 格式、月份、非法日历日期、混入其他文本、混合时间格式及倒序范围均返回具体字段错误，审计可查看同样的修正要求。
- 未发布维度与重复维度分别提示；修正后查询仍保留相同时间字段、分组与完整总计。
- 授权失败、未知字段拒绝、运行租约、幂等与已有非指标工具行为继续回归。
