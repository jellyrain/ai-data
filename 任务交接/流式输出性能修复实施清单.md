# 流式输出性能修复实施清单

日期：2026-10-08。用户在排队诊断后回复“开始”，批准修复积压片段与同批重复读取。主代理单独实施，依赖操作为 0。

## 目的与范围

解决模型持续生成时小片段提交积压、模型结束后页面仍长时间追加文字的问题。保持现有事件合同、当前权限检查、租约事务、工具顺序及断线回放。

| 文件范围（相对 ai-data/apps/api）                                                                   | 工作                                                                                         |
| --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `src/harness/codex-session-router.ts`                                                               | 合并尚未执行的相邻同段文字；已经提交中的片段保持稳定；工具、压缩、消息完成形成顺序边界。     |
| `src/runtime/analysis-executor.ts`、`sql-runtime-repository.ts`、`runtime-types.ts`                 | 流式复核只读取当前上下文指纹，复用原指纹算法；当前运行证据由提交服务检查，历史运行继续复核。 |
| `src/analysis-runs/analysis-run-service.ts`                                                         | 消息提交在同批复用刷新后的身份；提供一次授权复核的状态与事件读取。                           |
| `src/routes/analysis-routes.ts`、`src/app-types.ts`                                                 | SSE 使用状态与事件联合读取，保留提交唤醒、一秒兜底与游标回放。                               |
| `tests/harness/`、`tests/runtime/`、`tests/analysis-runs/`、`tests/routes/`、相关测试夹具及集成用例 | 慢提交、顺序、权限变化、租约与回放验证。                                                     |
| `任务交接/`                                                                                         | 实施与交付说明、流程图、性能对照；README 追加入口。                                          |

## 行为场景与验证

1. 每秒输入 30 个文字片段、每批提交 250ms，3 秒输入后应在有限尾批内完成，文字完整且顺序一致。
2. 长时间阻塞提交时，连续同段文字合并；工具、压缩和不同消息之间保持发生顺序；提交失败或取消后停止后续文字。
3. 每批仍检查当前身份、知识与策略指纹、历史和本轮证据；权限变化后拒绝交付。
4. 事件事务继续拒绝旧租约、过期租约和取消后的写入。
5. SSE 提交后及时唤醒；终态、分页回放及断线游标保持一致；读取过程中权限撤销不能交付已读事件。
6. 先运行新增测试确认目标失败，再实施；完成 API 全量测试、相关类型和 lint、格式、隔离 SQL 与确定性对话检查，并复跑相同模拟输入的时序对照。

验证直接使用已安装 CLI。数据库验收使用随机隔离库，完成后清理。实际模型和浏览器检查以最终记录中的实跑范围为准。
